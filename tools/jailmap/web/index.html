Degraded what could not be read this window

    Read-only. jailmap runs jls, sockstat, ifconfig, ps -axo, pfctl -s info, pfctl -s rules and jexec <jail> ifconfig, and refuses to run anything else — pfctl in any mode but -s included. It never starts, stops or reconfigures anything.

    MCP upstreams are inferred. They are stdio subprocesses with no sockets at all, so the only evidence is the process table: a process whose executable is named mcp-gateway, and its direct children. jailmap does not read the gateway's registry or database to find out which upstreams should exist — an observability tool that depends on the health of the thing it observes is useless exactly when you need it. The names shown are executable names, not registry names.

    Exposure is about the bind; reachability is about pf. A routable bind behind a default-deny inbound ruleset is not the same finding as one with nothing in front of it, and both are shown. jailmap does not evaluate a pf ruleset beyond looking for an unqualified block ... in ... all; anything else, an unreadable pf, and a VNET jail's own pf instance are all reported as unknown.

    What this cannot see. UDP has no connections, so the OpenVPN tunnel never appears as an edge however busy it is. Sampling can still miss a connection shorter than the interval. Sockets the kernel cannot attribute to a live process show ?? for the process. Addresses that belong to nobody in the address book are printed as-is and marked unknown, never guessed.
